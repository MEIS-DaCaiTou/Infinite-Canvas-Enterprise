## 1. 架构边界

| 主题 | 当前边界 | 不能冒充 |
| --- | --- | --- |
| 数据 | SQLite＋文件/JSON 单机持久化 | PostgreSQL、多节点事实库 |
| 服务 | Gateway＋loopback Canvas 双进程 | 水平扩展/HA 微服务 |

| 桌面 | 维护线薄 EXE 工具与入口 | 完整员工桌面客户端 |
| 测试 | 对应提交、安装状态和设备范围 | 所有客户或永久生产批准 |

## 2. 持续技术债

- `main.py` 聚合路由、存储和 Provider 协议；按领域提取服务/适配器，保持 API/画布体验，不一次大重写。
- 前端重复状态与资源/任务逻辑；先固定回归与接口类型，再局部模块化，不扩张多套框架。
- 覆盖层依赖 Gateway，内部服务暴露会绕过隔离；新增路由回归请求、响应和事件。
- SQLite 写入串行和长事务要实测等待、延迟、队列，不以“数百用户”猜容量。PostgreSQL 迁移是数据工程，不仅改连接字符串。
- 文件与归属库不是天然单事务，需要回执、幂等修复、资源引用和对账，备份不能代替一致性。
- #156 已提取图像目录/参数/请求构造，鉴权、分派、查询、解析与归档尚未统一；个人模型已共用，尺寸等逻辑仍重复。关联业务改动处理完整边界，不预建动态插件/通用参数语言。
- 内存任务/部分回执不等于任务中心；响应不明禁止再次自动付费提交，相关止损 PR 的合并状态须核验。
- #123 已合并的原任务续查补齐已收到 ID 的通用画布图像回执与批量成员保留；尚未收到/保存 ID 的受理窗口、完整 Provider Attempt、视频、取消、自动对账和费用账本仍未完成。两类画布单任务 GUI 已用本机模拟供应商验证，批量部分结果核心检查不代表完整 GUI 或真实付费验收。

## 3. 交付与升级风险

数据接线、#115 已完成，09.9 已有正式改表目标；真正缺口是维护线回归 main、统一安装维护与长期更新协议，不能说“全部未实现”。

- #132–#135 在维护线合并，#136 Draft，MERGED 不等于 main。
- 同一个 09.6 Release 可能有基础/激活治理库，核验完整身份，不能只数对象。
- main 已有固定原生入口、RegisterLifecycle 标准卸载与同版保留数据重装；未知来源/锁、完整 GUI 和客户矩阵仍有缺口，不再将已合并基础称为未开发。
- main 分页最多 1000 Release，连续路径最多 8 跳；#154/#155 已合并执行器、原生工具和连续路径，在线 handoff 阻断、整机重启及未知未来 Schema 仍未验收。固定旧工具不承诺无限跨度。
- 准备失败不停止服务；恢复未知保留阻断。接受新写入后不还原旧快照丢新数据。
- 网络不可达保留校验离线资产，源码 ZIP 不是正式更新包。

旧分支处置见 [Runtime 历史记录](../ops/HISTORICAL-RUNTIME-HOTFIX-BRANCHES-2026-09.md)，不是另一条随意合并主线。

## 4. 安全与验证

403 先核验角色、治理状态、API 和审计，不放开权限/删对象。尚无全部部门费用、SSO、分布式限流或远程诊断闭环；未签名风险披露，不关闭系统保护。

安装副本、Mock 生命周期、独立 HTTP、真实 Supervisor、客户图形操作分别记录。普通测试不能自动证明所有杀毒/代理/ACL、长期容量、实时计费或全部客户迁移。独立干净设备不是前提；缺口如实披露，不无理由重跑全门禁。
