## 7. 阶段 5：资源缓存、前端与员工桌面客户端

- 资源按内容身份/哈希引用，分离原图、缩略图、预览；增量验证 ETag/Range/懒加载/缓存指标。

- Vue 3＋TypeScript 先试做一个真实管理页面或局部功能；验证接口、类型、测试和旧页面共存边界后再定型，不一次重写画布。
- 员工 Windows 桌面界面借鉴成熟客户端的导航、工作区和更新体验；不是照搬品牌/私有协议。Electron/Tauri 用同一小实验比较后再决定，不开发两套成品。

## 8. 阶段 6：PostgreSQL 与高可用

- 标准服务器运行在适合的既有工作包内逐步建立：优先评估 Linux 真实依赖，落实外置配置、无交互启停、健康/日志、服务管理与可重复交付；平台特有逻辑留在适配层。服务器兼容调查和业务接口边界可提前随当前阶段推进，不等于已部署。
- 长期保留 SQLite 单机；团队 PostgreSQL 采用相同领域服务和存储接口。接口边界在早期设计，不等到迁移才重写全部业务。
- SQLite → PostgreSQL 专门迁移向导、完整性/权限/费用校验和失败恢复；不夹带在普通应用更新。
- 基于写入等待、队列积压、延迟、存储与恢复指标决定容量，不按“几十/几百用户”宣称能力。
- 后续以 100/200/300 活跃用户的混合负载验证画布、AI 受理/查询、素材与实时连接；活跃用户数不等于同时付费请求数。按瓶颈扩容，不预设微服务、Docker、Kubernetes 或 Redis 为前置目标。
- 团队任务领取、幂等、并发/连接池/索引、共享素材存储、多 Worker 和故障恢复有专项验证。
- Redis 只按明确需要引入；多节点升级、排空与 PostgreSQL 备份/PITR 不复用单机文件回退假设。
- 在扩展生产规模前确定 RPO/RTO、备份保留与灾备证据；真实容量风险可提前触发专项设计评审。

验收：单节点退出不丢受理任务，并发权限/费用一致；迁移和多节点升级/灾备各有可重现证据。
