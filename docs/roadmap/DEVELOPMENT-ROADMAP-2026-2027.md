# Infinite Canvas Enterprise 开发路线图（2026–2027）

更新时间：2026-10-05

## 1. 唯一实施顺序与当前落点

> 安全修复 → 数据升级能力 → **统一安装与在线升级体验** → 部门与可靠任务 → 资源缓存与桌面客户端 → PostgreSQL 及高可用 → 企业集成

这是一条交付依赖，不是必须完全串行的调研日程。测试、文档、日志、模块化及未来接口设计可随当前任务推进；未经升级/恢复验证的新业务表不能先推给客户。规模风险若提前出现，按实测调整并记录决定，不能机械等到“第六阶段”才考虑数据边界。

最新完成/分支/发布状态只见 [CURRENT_PROJECT_STATUS](../CURRENT_PROJECT_STATUS.md)。当前主线已完成主要安全与数据基础，阶段 3 部分实现；维护线已发布 09.9 与通用升级工具验收包，但没有统一到 main，也没有完成全部安装维护闭环。当前优先收敛交付，不再按每个应用版本复制工具。

统一设计见 [ADR-DELIVERY-001](../decisions/ADR-DELIVERY-001-UNIFIED-INSTALL-UPDATE-LIFECYCLE-2026-10.md)。其中 Accepted 是已认可方案，下面待办不是“已经可用”。

## 2. 阶段总览

| 阶段 | 当前判断 | 主要退出条件 |
| --- | --- | --- |
| 1. 安全修复 | SEC-P0 / Runtime 主要成果已合并；持续加固 | 已知高风险绕过有回归，角色/入口语义一致 |
| 2. 数据升级能力 | 备份、登记、迁移、验证、恢复已接线；旧源按证据核验 | 每次实际改表目标具有旧源安装副本及失败恢复证据 |
| 3. 统一安装与在线升级 | **当前主任务，未收口** | 新装/接管/更新/修复/保留数据卸载、固定入口和可恢复更新共用引擎 |
| 4. 部门与可靠任务 | 待落地；付费止损 PR 待主线收敛 | 受理/回执/费用可持久查询、重启恢复、隔离和对账 |
| 5. 资源缓存与桌面客户端 | 待落地，不等于当前启停 EXE | 资源身份稳定、缓存可控、员工客户端只更新自身 |
| 6. PostgreSQL 及高可用 | 目标设计；当前未部署 | 团队迁移/并发/灾备、多实例升级可验证 |

## 3. 阶段 1：安全修复与持续回归

PR #108 Runtime、#119 浏览器/路由边界已经合并，#111 已关闭；不是下一轮再做一次相同修复。

- 保持 Gateway 为对外入口，未知请求、事件、归属默认拒绝。
- 角色、高风险操作、授权、审计在 UI/API/任务/更新中一致；403 要区分真实无权与未激活/前端契约问题，不“放宽权限修按钮”。
- 新装和旧安装接管分别验证安全治理状态与管理员操作。
- TLS/可信反代、限流与策略边界随部署需要加固；按领域拆解 Gateway/interceptors（#116），避免无关整片重写。

验收：攻击面和角色矩阵有自动回归；主线安全合并不冒充所有客户已经激活安全治理。

## 4. 阶段 2：版本化数据与恢复

#109、#114 已通过 PR #120/#121 完成基础复核和更新中心接线；PR #130 补齐旧库先备份再登记。每个新迁移仍需专项证据。

- Release 声明准确来源、数据库结构/版本、迁移步骤、更新协议、降级限制和磁盘需求。
- 数据库升级前一致性备份；程序、数据库、配置、画布及素材引用的保护策略明确，大文件不盲目全量复制。
- 覆盖迁移事务前/中/后、指针切换、目标启动、恢复失败及结果返回丢失。
- 画布 JSON、配置、任务与索引格式也纳入版本兼容；启动不得悄悄改表。
- 使用真实公开源资产安装副本，不用空数据库代替旧客户状态。

验收：成功保留数据并符合目标身份；失败恢复匹配的数据库、指针和程序；不明恢复保留阻断。现有 09.6 的 18/28 对象差异是必要矩阵，不通过删除对象规避检查。

## 5. 阶段 3：统一安装与在线升级体验

### 3.1 先收敛已存在的交付分叉

- 10-05：文档 PR #137 与固定入口 PR #138 已合并主线，复用准确 Head 的通过检查；版本无关构建和编译后指针/拒绝契约已回归。安装接线候选从 `main@65d3f8a` 继续，完成新装固定入口、实例 ID 和已有安装入口修复的分支实现/定向验证，见 [DELIVERY-1](../ops/DELIVERY-1-FIXED-NATIVE-ENTRY-2026-10.md)；不是阶段 3 退出。
- 审查维护线 PR #136 及其当前 CI/图形验收结果，处理固定入口、安装定位与失败提示；不把只读检查当真实启停验收。
- 对照 main 与 PR #132–#136，收敛业务/Runtime/迁移/工具差异；避免复活过时文档、丢失安全修复或保留长期双主线。
- 先接回固定入口及构建，再核对旧库变体、登记/迁移和恢复引擎；不因整分支覆盖丢失主线安全/任务实现。共用 Runtime，不在 C# 层复制 Supervisor 或迁移。
- 一个稳定安装身份、目录契约、发布清单和正式/开发通道；不改已公开资产，不仅提高 main 的 VERSION 就发布。
- 通用工具固定到 09.9 是现阶段受控接管范围，不把它宣传成未来所有版本的自动升级器。

退出证据：准确源/目标提交和兼容矩阵清晰，工具验收与主线实现边界明确；后续安装/更新工程从一致基线开始。

### 3.2 一个安装维护产品

- 当前窄范围候选只接入新装与入口修复，非完整程序修复或应用升级。先完成其 CI/审查、真实 Runtime 启停与安装 UI 验收，再扩展保留数据卸载、程序/环境修复和中断恢复；不按版本复制工具。
- 新装、已有安装更新/修复、多实例选择、损坏安装检查/恢复统一入口；不重复初始化。
- 固定 EXE 与快捷方式长期稳定，随当前指针启动，提供状态、启停和脱敏诊断。
- 正常使用自带运行环境；用户无需 Python/pip/BAT/命令行。
- 修复不重建数据库或重置账号；卸载默认保留业务数据，重装先核验；明确数据清除的独立确认。
- 旧安装接管后登记实例身份和路径，不强制搬迁。个人安装与机器级服务分开权限。
- 未签名包标注来源、哈希与风险，不关闭 Windows 安全保护，不要求付费证书或干净设备。

验收矩阵：首次安装、重复运行安装器、定位失败、多实例、损坏程序、保留数据卸载/重装及未知来源阻断。不能仅通过新装成功就宣布完整维护完成。

### 3.3 日常更新与长期跨版本

- 网页、安装维护 EXE、固定入口和恢复界面共用更新引擎。
- 一次确认显示真实阶段；持久作业独立于浏览器/窗口存活。
- 完成经验证的路径目录扩容、更新器接管/自身更新、跨重启多跳授权和检查点。直接可达就直接升级，只在必要时经过桥接。
- 正式通道不能依赖开发中间版；不兼容的降级禁止，仅当前可证明的来源可升级。
- 升级前准备成功，再进入维护；控制业务写入。未提交暂停、已受理继续查、未知待对账；持久任务尚未实现时明确要求无活动任务。
- 恢复后核验服务、数据库、指针和审计再解除阻断。业务已开放写入后不能恢复旧备份丢新数据。
- 目录分页/缓存、支持期限、资产与备份保留按容量明确，不承诺无限老版本；当前 50 Release/8 跳上限需工程补齐。
- 管理员赋予/撤销及操作授权 403 在准确新装/接管副本复现并回归，不能跳过安全激活。

退出证据：主线、安装副本、现有 CI 与必要现场回归分别记录；关闭窗口、断网/重启、各跳失败、未知状态、数据保留与授权边界有证据。无需独立干净 Windows 设备，不无理由重跑 PR 全套门禁。原 #115 已完成，不借同一名字重复要求全套演练。

## 6. 阶段 4：部门与可靠任务

### 4.1 费用止损先收口

审查并收敛 PR #123：供应商可能已受理、响应丢失或本地超时时禁止自动再次付费提交。沿用其定向测试和已有 CI，确有影响再补测；不能假定所有 Provider 都支持幂等提交。

### 4.2 持久任务中心与独立供应商适配

- 持久保存任务、提交尝试、供应商任务 ID、状态、结果引用、错误、计价归属和对账记录（#110）。
- 请求受理、提交和查询分开；查询重试不重新生成。未知结果进入 UNKNOWN/RECONCILING，不伪装成失败。
- SQLite 用受限事务及单写入者策略领取；PostgreSQL 以后用相应并发领取，不把 PostgreSQL SQL 原样写给 SQLite。
- 每个常用供应商独立参数/能力适配与校验；同步、异步、取消、回调、费用不靠猜测共用接口。不继续堆入 main.py。
- 用脱敏真实案例与受控测试验证一个常用供应商闭环（#113）；没有预算时先模拟并记录未验证边界，不反复提交昂贵任务。

### 4.3 部门与费用治理

- 组织/部门/项目/成员关系与内部用户身份；凭据可隔离、加密、只写不回显、轮换和审计。
- 固化每次任务的部门、供应商、模型和计价版本；费用账本区分预估、受理、结算、退款/冲正与未知。
- 管理后台统一任务列表、筛选、费用与预算视图；费用能追到任务和供应商回执。

验收：重启和网络中断后可恢复/对账，已受理任务不重复付费；部门之间无越权，表变更可通过阶段 2/3 的交付体系到达旧安装。

## 7. 阶段 5：资源缓存、前端与员工桌面客户端

- 资源按内容身份/哈希引用，分离原图、缩略图、预览；增量验证 ETag/Range/懒加载/缓存指标。
- Web、主机缓存和共享存储职责分层；软删除、引用、保留期、清理和悬挂引用一致。
- Vue 3＋TypeScript 先试做一个真实管理页面或局部功能；验证接口、类型、测试和旧页面共存边界后再定型，不一次重写画布。
- 员工 Windows 桌面界面借鉴成熟客户端的导航、工作区和更新体验；不是照搬品牌/私有协议。Electron/Tauri 用同一小实验比较后再决定，不开发两套成品。
- 员工端本地 SQLite 仅缓存/设置；支持可选数据盘、容量、后台/断点下载、本地设计工具。团队服务器更新不从普通员工端触发。
- 固定 EXE 的启停维护能力在阶段 3 落地，无需等待完整桌面 UI。

验收：缓存清理不毁业务数据、离线后可恢复、磁盘不足/损坏可诊断；桌面与服务端兼容约定明确，客户端可独立安全更新。

## 8. 阶段 6：PostgreSQL 与高可用

- 长期保留 SQLite 单机；团队 PostgreSQL 采用相同领域服务和存储接口。接口边界在早期设计，不等到迁移才重写全部业务。
- SQLite → PostgreSQL 专门迁移向导、完整性/权限/费用校验和失败恢复；不夹带在普通应用更新。
- 基于写入等待、队列积压、延迟、存储与恢复指标决定容量，不按“几十/几百用户”宣称能力。
- 团队任务领取、幂等、并发/连接池/索引、共享素材存储、多 Worker 和故障恢复有专项验证。
- Redis 只按明确需要引入；多节点升级、排空与 PostgreSQL 备份/PITR 不复用单机文件回退假设。
- 在扩展生产规模前确定 RPO/RTO、备份保留与灾备证据；真实容量风险可提前触发专项设计评审。

验收：单节点退出不丢受理任务，并发权限/费用一致；迁移和多节点升级/灾备各有可重现证据。

## 9. 阶段 7：企业集成

- 内部用户 ID 与外部身份关联；OIDC/SAML、目录/SCIM 按客户需求接入，禁止相同邮箱自动合并身份。
- 版本化 API/MCP/Agent 复用人工作业的权限、任务、费用与审计；不自建竞争性的通用 Agent。
- 委托限制项目、操作、期限、预算和设备，密钥不透传；离职、注销、失窃、预算耗尽后撤销可验证。

验收：身份关联可审计，撤销与费用可追溯；协议升级仍遵守安装角色和客户端兼容规则。

## 10. 横向要求与暂缺决策

- 结构化日志与 request/job/task 关联（#112）、权限/故障/浏览器定向测试、接口版本和模块化随功能实施。
- 本地诊断包先脱敏。可选远程诊断在有授权、开关、字段/留存/隔离设计之后实施；阿里云仅为资源提议，本轮未部署或上传。
- 中文 Release 说明固定源提交、应用/工具/数据库版本、通道、兼容源、迁移、失败恢复和未覆盖场景；资产不可变。
- 支持期限、目录分页上限、备份容量/留存、机器级服务生命周期、客户端协议支持窗口、云诊断运维责任仍需细化；不能默认为无限支持。
- 文档只更新唯一事实源与登记表，不再增加新交接包；历史结论保留但标记角色。阶段验收采用安装副本、定向测试及现有 CI，额外测试须有风险理由。

## 11. 禁止提前宣称

ADR、CI 或某台设备成功，都不能替代对应范围验收。统一新装/修复/卸载、更新器自更新、自动多跳、业务写入后任意回滚、统一任务/费用、完整桌面客户端、PostgreSQL/HA、远程采集、SSO/Agent 和签名安装器仍须按实际证据分别报告。完成的数据迁移基础与已发布 09.9 不能再误写成“全部未实现”。
