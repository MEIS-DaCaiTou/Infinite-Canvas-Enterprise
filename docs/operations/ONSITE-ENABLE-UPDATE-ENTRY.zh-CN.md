# 现场任务：受控启用统一更新入口，不执行版本升级

日期：2026-10-08。项目：Infinite-Canvas-Enterprise。

负责人已批准补齐更新入口，当前业务继续使用；不得临时修改现场代码。本文只授权部署配置维护，不授权应用升级、角色再次初始化、业务数据迁移或套用此前已过期的停机窗口。

- 安装根：`D:\Infinite-Canvas-Enterprise\install`；固定入口：根目录 `InfiniteCanvas.exe`。
- 安装 ID：`900a11f3042c4255ae8e39f6e640e2d9`。现场必须重新核验，不能仅凭目录名操作。
- 原 `Aidan02` 已受控提升为首位 `super_admin`，密码不变。不得再次初始化、新建替代超管、改密码或改用户 ID。
- 当前部署配置 `ENTERPRISE_UPDATE_ENABLED=false` 是更新入口被禁用的原因；权限表全局允许不覆盖部署禁用。
- 09.9 成员标签未区分超级管理员，更新拒绝提示过于笼统。源码修复经主线 PR 和新的完整发行资产交付，不在现场修改 `enterprise-static/admin.html`、Python、Manifest、资产哈希或版本号。
- 新版已经产生业务数据。此次失败只能恢复本次配置和同版服务，不得恢复旧 TEST、升级前数据库或版本指针。

## 2. 可使用的数据及保密要求

允许在本机核验本项目登记、指针、Manifest、Runtime 身份、配置、任务、日志和备份，使用合法账号交互登录完成检查。需要的配置、密钥只留本机受保护目录；不把整个环境、账号凭据、数据库或业务内容写入分享报告。不得硬编码、输出或修改用户密码。

输出位于 D 盘本产品产物根下的本次独立目录：

`D:\Infinite-Canvas-Enterprise-Artifacts\update-entry-enablement\<本次时间戳>\`

其中 `private` 保存受保护的配置原件、凭据相关检查及恢复材料，`share` 只保存脱敏结果。配置备份须保留原 ACL，限制当前执行用户及 SYSTEM；不能复制到公开分享位置。无需重新全盘盘点或复制大体量素材。

## 3. 阶段 A：现在可执行，不中断业务

1. 完整读本文；识别当前固定 EXE、安装 ID、指针、服务进程创建身份、端口和实际 CONFIG_ROOT。运行固定入口的只读 identity/status/health 或已核验的等价只读接口；若实际状态已变更，记录差异，不猜测。
2. 记录当前业务健康、Release 和监控/备份最近一次实际成功状态。保留原周期监控与 15 分钟版本化备份，不改变其到期、调度和运行账号。
3. 经合法原密码登录核对 `Aidan02` 的当前接口角色。只读查询 `/enterprise/api/update-mvp/access`，预期 `role=super_admin`、部署禁用、权限来源为超管；09.9 没有新接口字段时如实记录旧字段。只读核对权限表的 `system_update` 全局状态，不自动修改权限表。
4. 只读取准确配置中的目标项 `ENTERPRISE_UPDATE_ENABLED`，检查重复声明、路径/重解析点和其他来源覆盖。不得展示其余密钥配置。当前读取逻辑使用 `os.environ.setdefault`，运行进程/启动器继承的同名环境项可能覆盖文件；只核验这一项，不更改系统级环境或读取整段业务内存。
5. 在 private 留存准确配置文件原件、哈希、ACL 和恢复路径；准备只将该项从明确的 `false` 改为 `true` 的差异计划，不写生产配置。遇重复、歧义或来源冲突时先核清来源，不添加第二个同名配置项。
6. 确认同版固定入口停止/启动及失败恢复路径可用，最新版版本化备份状态正常；只查看，不通过试停机证明。无需测试模型生成、不调用付费 Provider、不重跑全部测试。
7. 未收到新的维护起止时间，则以 `READY_FOR_MAINTENANCE / NO_SERVICE_CHANGE` 汇报并停止；此时配置和服务未改变，不能写成“更新入口已启用”。不沿用 12:00、12:15 或旧恢复截止。

## 4. 阶段 B：仅在负责人提供的新维护窗口内生效

这是同 Release 配置维护，不是代码升级。开始前确认有足够时间完成一次受控重启及恢复；记录本次最终恢复截止和回退决策时间，至少为恢复预留 15 分钟。不要到截止后继续等待页面或人工回复。

1. 核对阶段 A 计划和配置哈希仍一致，监控/备份正常，无活动生成任务或未处理的付费任务；有活动任务时停止进入本阶段，不取消或重提任务。
2. 只改实际 CONFIG_ROOT 中 `enterprise.env` 的唯一目标项，保留其余字节、换行、编码和 ACL。使用同目录受管临时文件与原子替换并核验单项差异；不能覆盖整份默认配置、清空密钥或修改不可变 Release。
3. 通过固定入口及其共用 Runtime 完成受控同版停止/启动。参考 CLI 为 `InfiniteCanvas.exe --stop/--start --install-root <批准根> --result-file <本次private结果>`；先验证该现场二进制支持，不把主线源码或开发产物当现场命令。只处理经绑定的本实例，拒绝广域 taskkill、删除锁/状态或自行改 Supervisor。固定入口拒绝或恢复状态不明时停止并报告，保留同版最新数据。
4. 必须创建新的 Runtime/子进程，不能只重启继承旧环境的 Gateway 来假定部署开关已刷新。若本次专用启动进程继承该项 `false`，可仅在该子进程环境中移除这个已经核实的单项，让准确配置加载；不要修改机器/用户全局环境。无法核清实际生效来源时恢复原配置，不绕过校验。
5. 新启动后核对同一安装 ID、同一正式 Release/指针、同一数据库位置、外部端口、健康、原账号登录与已有画布/素材只读。不能接受“HTTP 200”代替服务归属核验。
6. 核对更新授权：原账号仍 `super_admin`、当前 `can_operate=true`，部署及权限条件均允许。09.9 旧接口只有组合字段时，结合配置、专用启动环境和新进程身份核验；不得要求旧页面显示修复后的标签。仅做一次只读更新版本查询，不调用 prepare/execute/recovery-clearance、不点击更新确认，不选开发通道或强制目标。
7. 新版本查询失败与业务失败分开：网络、仓库权限或没有更高版本如实记录，不假造可升级路径；业务仍可用时，不为查询重复停启或回到旧 TEST。若授权仍禁用、角色/服务归属异常或重启失败，按本次配置维护恢复预案处理。
8. 需要恢复时只恢复 private 中本次配置原件和 ACL，通过同一固定入口恢复同版服务；不恢复旧数据库、不改角色和指针。记录恢复后的实际健康和最新数据位置，保留所有业务写入。
9. 确认原监控已采集新进程身份、15 分钟备份至少一次实际成功，再汇报。注销 Windows 后原任务不运行的限制仍在，不把本次改配置当机器级运行保障。

## 5. 汇报与后续统一版本更新

只生成一份简明中文报告和小型脱敏 ZIP，不打包源码、配置原件、密钥、数据库或素材。报告包括：开始/结束时间、实际服务与 Release、安装 ID、开关前后状态、角色、是否重启/停机区间、查询结果、监控/备份实际状态、失败恢复结果及 ZIP SHA-256。

结果只能是：阶段 A `READY_FOR_MAINTENANCE / NO_SERVICE_CHANGE`；或阶段 B `SUCCEEDED`；或同版配置已恢复的 `ROLLED_BACK`；或无法核实恢复的 `RECOVERY_REQUIRED`。只读准备不冒充完成；配置开启不冒充新版页面已交付。

角色显示及更新原因修复先在开发端评审、CI 和完整资产构建中收敛。正式维护版本发布必须声明准确源/目标 Release、数据库治理状态、兼容路线、备份及失败恢复；未经这些检查不允许从 main 工作区直接拷贝文件到生产。未来由统一更新中心选择正式目标、确认一次、查看持久作业状态，不再现场改源码、Manifest 或数据库结构绕过检查。
