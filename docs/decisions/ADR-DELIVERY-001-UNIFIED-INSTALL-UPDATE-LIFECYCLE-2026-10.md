# ADR-DELIVERY-001：统一安装、更新与产品生命周期

状态：Accepted（设计已获项目负责人认可；不是实现完成或生产验收声明）
日期：2026-10-03
适用项目：`MEIS-DaCaiTou/Infinite-Canvas-Enterprise`

## 1. 决策背景与替代范围

客户线已经经历 09.5、09.6 到 09.9 的交付；准确 Release 相同的 09.6，仍可能具有发布时的基础数据库或后来显式激活的安全治理数据库。旧更新器不能理解后一种状态，页面升级曾被数据库身份检查阻止。不能用删除审计表、修改旧发布证据或反复尝试来解决。

现有“新装器＋页面更新＋历史桥接工具”尚未形成完整维护体系。本决策确立共同目标，取消按每个应用版本复制升级工具的做法；当前能力与限制只在 [项目状态](../CURRENT_PROJECT_STATUS.md) 记录，实施顺序只在 [路线图](../roadmap/DEVELOPMENT-ROADMAP-2026-2027.md) 维护。

本决策替代以下旧政策中的相关部分，不改写原有验收证据：

- [ADR-OPS-007](./ADR-OPS-007-GREENFIELD-PRODUCTION-BASELINE-AND-LEGACY-NON-MIGRATION-2026-07.md) 的“长期只允许全新安装、旧安装不迁移”产品范围。
- [旧运维路线](../ops/OPS-ROADMAP-2026-07.md) 的独立路线、数据工作暂停与旧阶段阻断。
- [INSTALL-UX-1 原记录](../ops/INSTALL-UX-1-SIGNED-ONE-CLICK-WINDOWS-INSTALLER-IMPLEMENTATION-2026-08.md) 中把付费签名及独立干净 Windows 设备作为当前交付前提的政策。

不可变程序版本、路径根隔离、默认拒绝、运行环境来源核验、Manifest 校验、授权审计和数据保护继续有效。代码中仍有旧限制时，应明确列为待整改，不能因本 ADR 生效而声称限制已解除。

## 2. 一条业务主线，三种部署角色

| 形态 | 安装内容与数据归属 | 长期边界 |
| --- | --- | --- |
| 单机版 | 页面/本地界面、业务服务、运行环境；SQLite 保存业务数据，素材存本地文件 | 长期保留；不是多节点共享数据库 |
| 团队服务端 | 集中业务服务、任务执行、管理后台；目标为 PostgreSQL 与受管理的素材存储 | 当前 SQLite 客户继续兼容；转 PostgreSQL 走单独迁移流程 |
| 员工桌面客户端 | 界面、缓存、设置和本地工具连接；业务事实在团队服务端 | 本地 SQLite 只做缓存与设置，不自动安装企业服务器 |

复用业务服务、权限、接口、迁移与测试，不复制三套功能代码。安装角色、运行实例和软件版本分别登记。员工客户端与企业服务端分别更新，以明确的 API/数据兼容约定协作，不要求所有员工同日升级。

Windows 优先。完整员工桌面界面与当前薄型固定 EXE 启停入口不是同一个交付。Vue 3＋TypeScript 是前端局部试做方向，未完成框架选型实证或画布重写；不并行扩张多个前端框架。

## 3. 一个安装维护入口

近期复用现有 Inno Setup；安装器负责界面和编排，不承载另一套业务或数据库迁移逻辑。

| 检测结果 | 默认处理 |
| --- | --- |
| 未安装且目标目录符合新装条件 | 首次安装；随包提供运行环境及固定入口 |
| 一个已核验实例 | 优先更新或修复该实例，不创建第二份 |
| 多个实例 | 显示位置、版本和角色，要求用户明确选择；不擅自合并数据 |
| 登记丢失、文件损坏或身份不明 | 检查、重新核验或恢复；不得当空目录重建数据库 |

必须提供安装、更新、修复、卸载。修复只恢复受管理程序、运行环境、固定入口和登记，不重置管理员、配置或数据库。卸载默认保留业务数据、素材及必要恢复记录；删除业务数据是另一个明确确认的操作，不捆绑在卸载、修复或缓存清理中。重装使用保留数据前先检查兼容性。

稳定产品标识不随版本变化；实例标识区分同一设备上的明确多实例。登记至少包含安装角色、实例 ID、安装/数据位置、当前 Release、更新协议和通道。路径是可变属性，不是唯一身份。旧安装首次接管要核验再登记，不能只凭文件夹名猜测。

定位按本项目登记、已验证固定入口和有限候选目录进行；不为“自动找到”而扫描整个硬盘或读取其他项目数据。已有客户目录不强制搬迁。个人安装与机器级服务安装分别设计权限；没有必要不申请系统管理员权限。

## 4. 稳定目录与启动入口

程序、数据、素材、配置、缓存、日志、备份和暂存区分开管理，遵循 [路径根 ADR](./ADR-ENV-004-PATH-ROOTS-AND-RELEASE-DIRECTORY-2026-07.md)。新程序放入独立 Release，不能覆盖运行中的文件；数据库、画布和素材不随程序包替换。

固定入口位于安装根，读取经校验的当前版本指针；快捷方式不指向某个 Release 内的 BAT。启动、停止、重启、状态、诊断均调用同一 Runtime 控制接口。正常客户操作不依赖安装 Python、pip、打开命令行或进入最新版本目录。

目录清理只处理明确属于本产品且可核验的文件。保留当前版本、恢复所需旧版本、正在使用的资产与有效备份；按容量/保留政策清理其他产物。开发构建和安装副本放在项目专用 artifact 根或受管工作区，禁止散落在盘符根目录。不能按名称猜测归属并删除其他项目文件。

## 5. 不同入口，共用一个更新引擎

管理后台、安装维护 EXE、固定入口及图形恢复工具调用共同引擎；不得各自实现备份、迁移、停机和回退。日常体验是“选目标、确认一次、看进度”，完整安装包离线运行也遵循同一兼容和恢复规则。

引擎的目标流程：

1. 核验实例、权限、准确源 Release、数据库及其他持久格式。
2. 计算到目标的可验证路径，下载/准备并校验全部必要资产。
3. 进入维护状态，处理任务与业务写入；未准备成功时不停止现有服务。
4. 必要时一致性备份，执行确定性的迁移并验证。
5. 切换程序和版本指针，启动、健康检查，再开放业务。
6. 记录完成；失败则恢复一致状态，或保留阻断并提供图形诊断/恢复。

确认授权要限定实例、计划、目标和有效期；不能为了跨重启而保存管理员密码。作业、计划、各跳检查点和恢复结果持久化，关闭页面、断网或服务重启后仍可查询。同一实例只能有一个有效升级执行者。

更新器及引导程序也必须有兼容协议和自身更新方案。旧更新器不理解新规则时，由已验证引导程序或完整安装包接管；正常支持范围内不要求客户运行脚本。引导程序不是允许绕过未知源身份的万能通行证。

## 6. 跨版本与通道规则

- 应用版本发布次数与数据库迁移步骤分开；同结构且协议兼容时可直接到目标，不要求逐个安装应用版本。
- 路由声明准确源/目标身份、数据库结构/版本、最低更新器协议、通道、完整资产和迁移/降级限制；不能只比较显示版本号。
- 确需中间更新器或数据迁移时，由系统完成经验证的步骤。每跳有独立检查点和恢复边界；后跳失败可以停留在已验证的中间版本，不能谎称整链已回到起始版本。
- 正式客户默认正式通道；开发版明确提示风险，不能成为正式升级必经站。回到正式版同样检查数据库兼容，不等于随便安装旧程序。
- 版本目录需要分页或经验证索引、缓存和明确支持期。当前“最近 50 个 Release、最多 8 跳”是实现上限，不是承诺“任意多年未更新都能升级”。
- 支持矩阵按可证明的历史基线和持久状态分类维护，不给每个版本复制代码。缺失资产、未知热修改动、未知数据库或不完整恢复作业应阻止执行并导出诊断。
- 停止支持旧基线前，先公布期限、保留必要桥接资产并提供图形接管路径。具体支持年限、资产保留期和磁盘预算仍待容量与发布策略确认，不能承诺无限期支持。

## 7. 数据与回退边界

不仅数据库，画布 JSON、配置、任务回执和资源索引也要有格式版本与兼容约定。禁止通过普通启动偷偷改变业务结构；首次初始化、显式安全激活和正式迁移要区分。

升级尚未开放业务写入时，可以恢复升级前的一致性备份及匹配程序/指针。新版本已经接受业务写入后，不能直接恢复旧快照丢掉新数据；应选择兼容回退、经过验证的保留新数据迁移或向前修复。此写入隔离边界须有测试，不因“能换指针”就声称任何时候都可回滚。

恢复结果不明时进入 `RECOVERY_REQUIRED`，保留证据和阻断；不能删除锁/状态文件重试。图形恢复必须核验数据库、指针、服务和审计后解除阻断。PostgreSQL 部署设计自己的备份/PITR、连接排空和恢复协议，不照搬 SQLite 文件替换。

SQLite → PostgreSQL 的产品迁移单独确认、演练和校验，不夹带在普通应用更新中。大文件仍在文件或对象存储，数据库保存归属、状态、哈希和引用。

## 8. 任务、诊断与发布信任

已确认的升级任务规则是“未提交暂停、已受理继续查询、未知待对账”。查询已受理任务不等于再次提交；本地超时不是重新付费的理由。规则依赖持久任务及供应商回执能力；完成前，工具只能如实要求无活动任务，不能宣称已经自动恢复内存任务。

诊断分为本地完整脱敏包和未来可选远程采集。远程采集须有管理员授权、客户端告知、可撤回开关、最小字段、限流、留存/删除策略及租户隔离；默认不上传账号凭据、提示词、画布、原图/视频或数据库。阿里云服务器是后续资源提议，不等于已经部署或授权上传。

无付费签名预算时可交付明确标为未签名的 EXE，公开可信来源、哈希和限制；不关闭 Defender/SmartScreen，不冒充 Windows 发布者身份。发布清单的免费密码学签名可另行建设，但不能替代系统发布者签名。独立干净 Windows 设备不是前置条件；安装副本、定向测试、现有 CI 和必要现场回归仍需保留。

一个发布构建产生同一源提交的安装包、在线资产和离线维护包。应用版本、工具/更新器协议版本、数据库版本分别记录，中文说明写清通道、兼容范围、迁移、恢复与未覆盖场景。已经公开的资产不可就地改写。

## 9. 落地与验收

具体任务只在 [路线图阶段 3](../roadmap/DEVELOPMENT-ROADMAP-2026-2027.md#5-阶段-3统一安装与在线升级体验) 排队：先收敛维护分支和文档基线，再完成安装维护、自动更新与恢复闭环，然后扩展业务。

核心矩阵包括首次安装、重复安装识别、多实例选择、旧安装接管、固定入口、修复、保留数据卸载/重装、长期跨版本、更新器接管、任务/写入隔离、数据保留和失败恢复。每一项记录代码/CI/安装副本/现场证据，不能用单设备成功代替全部产品形态验收。
