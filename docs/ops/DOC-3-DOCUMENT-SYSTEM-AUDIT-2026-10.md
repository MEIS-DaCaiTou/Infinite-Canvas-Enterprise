# DOC-3：项目文档体系全量审查与整改

审查日期：2026-10-03
项目：`MEIS-DaCaiTou/Infinite-Canvas-Enterprise`
代码基线：`main@7905ecf39efabeb3101d7b63c709d8dcd230c9a0`
本轮范围：文档及开发侧只读检查；未更改产品业务、数据库、安装器或客户设备。

## 1. 结论

**现有分层基础合理，现行状态维护和交付边界需要整改；不必重建全部目录，更不能把历史证据当垃圾删除。**

已有唯一索引、状态/架构/路线分离、ADR、领域实施记录、Code Wiki 与验收目录，部分旧文件也已有历史标记。问题主要是后续发布进展没有同步到这些入口，维护分支与主线差异缺少统一说明；旧正文中的任务/强制前提还可能被误读。

本轮将动态事实、已认可设计、未来队列和历史证据重新归位。新增一份决策、一份审查记录和一份机器登记，不再建立另一套交接包或路线图。

## 2. 范围、方法与证据限制

审查前 main 有 **120 项受 Git 管理的 Markdown／文本资料**：115 项说明/参考/依赖资料，另 5 项许可证、vendor 或运行时提示词资源。另外阅读 `enterprise.env.example` 的配置语境，但不把真实环境配置、未跟踪客户数据、二进制包和日志纳入文档清理。

方法：

1. 全量路径/角色登记与全文规则扫描；关键现行事实源、相互引用和冲突段落专项复核。
2. 对照当前源码中迁移/更新、Runtime、新装器与目录边界，避免只根据旧规划写“已实现”。
3. 只读核验 main、相关 PR/CI 与公开 Release；维护分支只作为其准确提交的输入，不改动。
4. 核对项目负责人此前反馈；本轮不重新执行历史测试、客户升级、付费模型调用或原始日志分析。

整改后原 120 项全部保留；增加本 ADR 与本审查共 2 项 Markdown，登记共 **122 项**。JSON 登记、检查脚本、单元测试与 CI 文件不计入 Markdown/文本数。

登记表记录所有资料的角色及必要替代关系，不等于每份历史正文都改写到最新版本。外部链接没有全面可达性/内容审查；自动检查也不证明文字语义、业务行为或客户兼容。

## 4. 当前合理的文档体系

| 层级 | 职责 | 维护方式 |
| --- | --- | --- |
| 入口 | README、docs/README | 导航，不复制完整状态 |
| 唯一权威 | CURRENT、架构、路线、范围/章程、开发/代码/安全、测试、统一交付 ADR | 每个问题一个出处，日期与证据范围明确 |
| 代码/集成参考 | Code Wiki、工具 README、检查清单 | 对应模块变化时局部更新 |
| 决策 | ADR | Accepted 不等于实施；被替代条款显式记录 |
| 实施记录 | ops/data/security/env | 固定时点证据，“当前”只属其记录时点 |
| 历史方案/来源 | 旧路线/蓝图/来源教程 | 不再排期或给客户普通操作指令 |
| 冻结证据与资源 | env/evidence、许可证/vendor/运行时提示词 | 原始字节保护；变更另有理由和审查 |

[document-register.json](../document-register.json) 是清单与机器角色约束；[docs/README](../README.md) 是导航。登记不能再承担另一份任务计划或客户版本支持目录。

## 6. 文档检查与保护

检查命令：

```powershell
py -3.11 -B tools/check_docs.py
py -3.11 -B -m unittest discover -s enterprise/tests -p test_documentation_contract.py
git diff --check
```

只读检查覆盖受 Git 管理及未忽略新资料的登记闭包、唯一权威、权威复核日期、本地 Markdown 文件/标题链接、已登记替代指向，以及冻结证据/资源哈希。Git 命令仅本地读取，不联网、不访问客户安装。

CI 为独立轻量文档任务，不修改既有企业测试的授权或风险政策；本轮不手动重跑无关全套门禁。不能用这项检查替代所有 Markdown 方言、外链、源码中的路径引用或人工语义审查。

本轮未删除/移动原有资料，未修改冻结验收、法律/vendor/提示词资源，未清理磁盘目录，未改用户其他项目。冻结哈希仅将 CRLF 规范化为 LF，以适应 Windows 与 CI 的 Git 文本换行；原证据内容不重写，并另用 Git diff 核对。

## 8. 以后怎样避免再次失控

任务完成时按受影响范围更新事实源，记录层级；新增资料先选择角色和现有入口，必须登记。不再恢复四份旧交接包、不再为每个版本复制升级规划。

历史资料不等于没有价值；本轮采取分类和替代，不用粗暴删除“解决”数量。未来若合并/压缩长期重复参考，另做范围清晰的文档任务，核对 Release 构建引用与许可证，保留 Git 可追溯性。
