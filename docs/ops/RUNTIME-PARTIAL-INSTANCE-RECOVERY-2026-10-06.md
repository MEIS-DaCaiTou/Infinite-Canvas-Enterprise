# 部分运行实例恢复修复（2026-10-06）

项目：`Infinite-Canvas-Enterprise`。范围：客户维护分支 PR #136；不表示已合并到主线，不改原有 `2026.09.9` 应用资产。

## 故障与处理优先级

现场导出的诊断表明，09.5 的网关在升级前已退出，上游仍由原 Supervisor 管理；旧入口把“两个子服务均健康”当作受控停止的前提，因此升级准备后不能发出 STOP，报 `NATIVE_UPGRADE_CONTROLLED_STOP_FAILED`。该次作业未进入数据迁移或版本切换，不能把服务中断归因于数据库迁移失败。首次退出的操作系统触发原因尚未确定。

本轮优先恢复当前版本服务，再验收升级。不得要求客户删锁、结束任意 Python 进程、修改发布证据、覆盖旧代码或重装数据库；不得把命令行维护流程推广给客户。

## 实现

- Windows 监听检查改用原生 `GetExtendedTcpTable`，分别核验 IPv4/IPv6 监听 PID。不启动 netstat 或依赖控制台输出；查询失败、未知或外部进程仍阻止操作。
- 停止控制权与健康就绪分开。完整核验安装、指针、Manifest、Python、launch context、Supervisor/lock/命令身份后，允许其停止自身部分运行的 Job；此授权不允许未知实例启动、重启或执行升级。
- STOP ACK 不能单独证明安全：继续确认原进程世代退出、端口为空、锁和待处理 STOP 已收口，才允许开始迁移或替换服务。历史 `stop_incomplete` 只有在这些新鲜证据齐全时才能收口为停止成功。
- 历史安装使用新工具内嵌的已核验控制代码发送原有 generation/context-bound STOP。原安装目录文件不被补丁改写，原 Supervisor 仍是唯一进程所有者；启动和健康检查仍经原版本正式入口完成。
- 图形工具新增“恢复当前服务”，独立于“确认升级”。该操作取得原有唯一维护预约，校验、受控停止、重新核验来源、启动和检查当前版本；不执行版本迁移、不切换程序、不安装或改登记固定入口。
- 升级失败恢复时，先确认目标服务停止，再恢复数据库和版本指针；目标停止不明则 `RECOVERY_REQUIRED`，不在可能运行的目标下恢复旧数据库，也不自动重试。
- Worker 停止失败后，只有原版本指针与物理数据库仍可核验，且再次受控停止成功，才能尝试恢复原服务。摘要增加固定、有限、无路径/凭据的生命周期阶段与错误分类。
- 新 Runtime 在旧子进程确认退出且端口已清空后，按既有退避/崩溃预算重试被清理阻断的子服务。此修复在本分支；不能声称原有 09.5/09.9 核心资产已经获得它。

## 验证与证据边界

定向契约涵盖部分子服务、外部端口、查询失败、身份变更、ACK 非充分条件、恢复预约、目标停止未确认时禁止回退、旧版数据与审计保护，以及 APP_ROOT 写入审计。

真实历史安装演练使用准确公开 09.5 资产和内置 Python，执行原版本 Supervisor/Job/上游/网关 HTTP。仅测试包装器将 KnownFolder 和固定 host/child 路径引导到隔离安装副本，不修改历史文件；不使用假的 STOP ACK 或假的健康回执。

演练一复现网关退出、旧入口停止被拒绝；新控制代码完成 STOP，当前 09.5 原服务再次 HTTP 200，核对指针、画布、素材、配置、28 对象数据库及审计/引导记录保留。演练二启动真实目标服务后注入更新器验证拒绝，再由目标的已核验 Python 执行新停止协议，恢复数据库/指针并验证旧 HTTP。该包装器边界不是未经包装的客户操作系统入口验收。

本地结果、CI 结果、工具发布和客户验收须分别记录。客户服务是否恢复，必须由客户在原地址验证登录和原画布后确认；复制来的旧 PID 不代表本机活进程。本轮不自动开启遥测、不调用付费模型、不运行全套企业门禁。

## 图形恢复操作与下一轮

2026-10-06 用户已要求减少重复安装演练，由其直接进行现场安装和升级反馈。本轮工具采用“现场验收包”交付：只保留构建、资产及脱敏日志导出的定向检查，不宣称当前 CI 的准确历史启动演练已通过，也不据此合并 PR 或推广为正式客户批量升级基线。图形入口增加“导出诊断日志”，离线收集工具阶段、所选安装的 Runtime 当前／两份轮转日志及最近三项更新作业；不包括数据库、画布、素材或原始配置。包内记录每源及总体限制、缺失和截断，不能称为全部无限量历史日志；也不会自动上传。

下载新的独立工具修订，不用旧的 `unified-upgrader.1`。确认原安装根目录，先“只读检查”；确认无活动 AI 任务后，勾选确认并点击“恢复当前服务”。看到当前服务健康后，验证原网页、登录和旧画布；恢复操作不会把显示版本升级成 09.9。

若显示身份无法核验、外部端口占用、恢复结果不明或需要恢复，停止继续升级，导出本工具诊断摘要；不要删除 state、日志或备份。恢复成功后再单独验收“确认升级”。EXE 未签名；不得关闭系统安全保护。

下一轮是客户真实恢复/升级验收、修复回归主线及交付基线收敛；随后再接回缓存清理、入口中断恢复、卸载保留和可靠任务中心。普通业务新版本仍暂停，不复制按版本专用修复器。
