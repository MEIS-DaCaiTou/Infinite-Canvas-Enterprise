## 改动

成员行、角色筛选、统计和权限用户选择器区分 `super_admin` / `admin` / `user`；没有 `role` 的旧响应仍兼容 `is_admin`。超管行不再呈现与固定角色保护相冲突的普通管理按钮。

更新 access 响应新增部署开关、功能开关和拒绝代码，继续使用当前持久角色及原后端授权；页面区分缺少超管、部署禁用和全局权限禁用。状态重新加载时先隐藏危险操作；失败保持禁用，不发起升级。

构建器新增 build-time `same-versioned-schema-no-migration` 选项，复用已发布 v2 结构的真实 fixture；对已安装更新器的协议仍为 `same-schema-no-migration` / `code-release-pointer`。不能使用旧的未版本化 18 对象快照声明这个维护包。当前 v2 结构为 30 对象、版本 2、对象哈希 `cd8790a1ef22a97b96c76105b26f14c309ed02396249ab97d36034bb88d25284`；发布时还须核对完整 schema evidence 和 migration registry 与 09.9 相同。

## 最小验证和现场使用

运行维护定向回归、原更新引擎成功/目标启动失败路径、干净构建和资产校验、真实浏览器桌面/移动视口显示；不用客户数据库，不模拟付费生成，不重跑无关全套门禁。

现场任务书随资产交付：先保持业务运行完成下载、身份/备份/任务检查；新维护窗口内通过现有统一更新引擎执行明确目标版本，保留当前配置，仅受控启用部署更新开关，验收 Aidan02 标签、更新权限、原画布/素材并确认现有备份/监控接续。启用入口与执行维护更新是分开的授权操作。

程序切换失败时遵循作业记录恢复。已经开放业务写入后不得恢复停机前旧数据库或启动旧 TEST 写入者；相同结构只提供程序兼容性的基础，不等于任意旧版无损降级。没有新窗口不停止或重启生产服务。
