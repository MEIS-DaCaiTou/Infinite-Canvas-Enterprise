# 通用升级器与固定 EXE 入口

更新日期：2026-10-01。项目：`Infinite-Canvas-Enterprise`。

## 当前交付范围

本轮在客户发布维护分支实现统一的 Windows x64 升级工具，而不是再增加一个 09.5 专用工具。一个工具识别经核验的历史安装，将其升级到原有 `2026.09.9` 应用，并安装根目录固定入口 `InfiniteCanvas.exe`。不修改已经发布的 09.9 核心 ZIP、Manifest 或文件清单；工具有独立版本、构建记录和中文说明。

代码在 `codex/unified-upgrade-launcher-20261001`，基于客户维护分支 `codex/098-stable-bridge-20260929` 的 `c9074963ee701544a23b5e8e7bbdc759fe463208`，不是已合并的 `origin/main` 功能。提交、CI、公开下载回验和客户验收应分别记录；不能把测试回调视为客户设备真实重启。

## 历史来源与支持边界

`installer/windows/historical-install-catalog.json` 记录完整源 Release ID、Manifest、Python、完整代码清单和数据库发布证据指纹。盘点用 `tools/inventory_upgrade_sources.py` 将下载资产与 GitHub 公开资产的大小、SHA-256 和 Manifest v2 全部复核。不能只看“09.5”这类显示版本号。

| 来源 | 核验规则 | 目标 |
| --- | --- | --- |
| 公开 08.1、08.2、08.3、08.4、09.4、09.5、09.6、09.8 的准确安装 | 发布证据完全相同的 18 对象基础结构，或完整定义符合的 28 对象已激活安全治理结构 | 统一升级至 09.9 |
| 公开 09.7 开发版的准确安装 | 同样核验来源和两类结构；保留其开发版来源标记 | 可恢复到本工具固定的正式目标 09.9，不使开发版成为正式客户必经站 |
| 准确 09.9 安装 | 30 对象结构及数据库版本元数据必须与发布证据一致 | 不再迁移；补装或核验固定 EXE |
| 截图中保留的 08.5 现场版、代码被修改的热修安装、未知结构 | 缺少完整不可变发布资产或结构不匹配 | 明确阻止，保留数据与诊断；不删除表、不改旧证据、不猜测兼容 |

“28 对象”不是仅计数通过：核验原有对象、附加表/索引/触发器完整定义、账号治理状态、唯一引导标记、相符审计事件、数据库完整性及外键。附加审计数据原样保留。源目录存在额外 Python 模块或被修改的内置 Python 时，在执行它之前阻止。

后续新增来源以扩充这个数据目录和验证矩阵为主，不复制一个专用升级实现。新目标仍须固定发布资产、声明兼容来源、验证迁移及恢复；“通用”不表示任意未来版本可以随意跳转。跨重启自动多跳和长期版本目录扩容仍是后续任务。

## 客户操作

1. 下载同一个 `Infinite-Canvas-Enterprise-Unified-Upgrader-x64.exe`，双击打开。
2. 工具只从本项目登记、运行进程路径、产品快捷方式及工具附近有限目录找安装线索，不扫描全盘、不读取进程命令行。唯一且完整核验的候选可自动填入；多个安装或定位不完整时，请明确选择原安装根目录。
3. 可先点“只读检查”。确认没有未完成 AI 任务后，勾选确认并升级。旧版本任务尚在内存，当前不能声称工具已自动暂停、恢复或对账任务。
4. 工具先校验及准备资产，取得唯一升级预约，再受控停止服务。复用原有 DATA/更新引擎备份数据库、执行迁移、切换指针、启动及健康检查；失败时恢复数据库和版本指针。
5. 成功后使用安装根目录的 `InfiniteCanvas.exe` 或桌面固定快捷方式。该入口每次读取 `state/current-release.json` 并校验当前代码；升级和回退均不改变用户入口，不再找最新版本的 BAT。
6. 固定窗口提供启动并打开页面、停止、重启、状态和诊断摘要。关闭窗口不会停止后台服务。完整运行日志仍从管理后台更新中心导出，摘要 ZIP 不等于全部运行日志。

未知恢复结果显示需要处理并保留阻断，不提示“安全回退成功”。不要反复点升级。固定入口安装/快捷方式失败单独报告，不把已经健康运行的应用升级误报为失败；根目录出现不属于本工具的同名 EXE 时不覆盖。

## 架构与目录规范

- C# 仅承担原生窗口、路径定位、资源校验和固定进程启动；Python 仍是业务、迁移与恢复的唯一实现。没有引入第二套 Runtime 控制器，没有重写画布、权限或供应商业务。
- 原生入口调用当前版本已存在的 `enterprise/runtime/launcher.py`，固定内置 Python 加 `-I -B`，不调用 BAT、PowerShell、系统 Python 或 PATH 上的程序。
- 不新建重复安装，不替用户选另一目录，不覆盖其他项目文件。源码位于 `installer/windows/native/`；测试位于 `enterprise/tests/`；构建、历史资产和安装副本统一在仓库外的产品 artifact 根目录。
- 临时引擎解包在产品专用 `TEMP/ICE/U/<随机本次目录>`，操作后仅删除本次索引中指纹未变的文件和空目录。升级作业/备份保留在选定安装的既有路径；固定入口记录及可恢复旧 EXE 保留在其 `state/` 下。
- 旧 Python 的路径上限仍存在。工具根据发布包最长临时路径提前检查，过长目录明确阻止，不自动搬迁客户数据。
- 工具不改在线授权规则。离线批准来源是内嵌核验目录，不接受网页请求自行传入“允许忽略数据库指纹”。管理员角色操作的既有 403 权限保护不在本轮放开。

## 构建和验证

`tools/build_unified_upgrader.py` 使用 `native-build-policy.json` 指定的 Microsoft 编译器包；同时核验下载包和编译器文件闭合清单。官方交付要求干净 Git 提交，重复编译两次且 EXE 字节一致，记录提交、tree、引擎包、目标和 EXE 哈希。`--allow-dirty` 只供实验，实验构建不得作为正式发布资产。

验证分为：

- 定向契约测试：来源目录、未知来源阻断、完整 DDL 识别、在线默认不放宽、预约先于停止、其他升级锁不被移除、失败作业收口、只读检查不创建目录、恢复未知状态不误报。
- 准确公开安装副本：9 个旧来源各自的 18/28 对象成功升级和目标启动失败回退，09.5 再注入迁移事务失败；核对数据库、版本指针、画布、素材、配置和审计保留。
- 编译 EXE：真实只读检查，损坏 Python/代码清单/结构/指针拒绝，固定入口随指针升级/回退，以及固定文件发布与不覆盖无归属文件。
- Windows CI 同样执行受影响范围，不额外重跑全套企业门禁。生命周期切换回调属于安装副本测试；目标独立 HTTP 启动与客户图形界面/真实 Supervisor 重启必须分开表述。

本轮不要求另一台干净 Windows 设备。未在客户设备完成图形和真实服务启停验收前，下载包应标明“工具验收包”，不能宣称所有客户都已验收通过。

## 签名、后续与未交付内容

当前没有付费签名预算，EXE 明确为未签名，不关闭 Defender/SmartScreen，也不将文件哈希冒充发布者签名。可信下载入口和 SHA-256 随包提供。

这不是新装安装器，也不是完整桌面客户端：员工桌面界面、缓存、自选磁盘及客户端自动更新仍待实施；新装安装器与固定入口的统一封装也需后续收敛。云端遥测没有启用，没有上传客户数据。

下一步先验收通用工具及固定入口的实际使用，再收敛客户分支与主线升级基线。业务顺序仍为安全修复 → 数据升级能力 → 在线升级体验 → 部门与任务 → 资源缓存与桌面壳 → PostgreSQL 及高可用 → 企业集成。可靠任务中心遵循未提交暂停、已受理继续查询、未知待对账，不因超时再次付费提交。
