# 09.5→09.6 同数据库结构过渡版

## 范围

本过渡版只针对已安装 `ice-2026.09.5-7609bb1b7cfa` 的 Windows x64 便携企业版。目标版本号为 `2026.09.6`。版本选择沿用已合并 PR #129 的正式版/开发版通道：管理后台列出完整、非草稿且版本号高于当前版本的 Release；正式版默认推荐，开发版明确标识。独立桌面客户端更新入口尚未交付。

第一跳不增加或修改业务表，不为旧客户库提前登记迁移版本。源/目标 `database_contract` 必须逐字段相同：`same-schema-no-migration`，数据库结构快照 SHA-256 为 `6b4a1deca34b5724217db868d1b8015f222982fddf63e952fb73e8d2966900c4`。`data`、`config` 和素材留在安装根目录，代码 Release 独立切换。后续引入新业务表须另做第二跳，走备份、迁移、目标健康与失败恢复，不把第一跳成功当作迁移验收。

## 发布验证

发布资产必须为同一个干净提交构建的 Windows x64 ZIP、`ops-release-manifest-v2.json` 和 `release-payload-inventory.json`。构建前验证复用的 CP314 运行时及其原始来源证据与正式 09.5 包一致；构建后验证三资产、物化文件树及数据库契约。使用从 GitHub 下载并完成三资产完整性校验的正式 09.5 包建立短路径隔离安装副本，由该包自带 Python 和旧更新器执行准备、切换及故障回退；检查模拟用户/画布归属、配置、数据库和素材保留。成功路径再用目标包自带 Python 做便携启动预检，并以独立进程监听随机本地端口验证 HTTP 页面可用。该 HTTP 探针不等同于真实 Supervisor 停机、重启及客户设备验收。

若隔离测试根目录过长，正式 09.5 更新器解包深层运行时路径可能遭遇 Windows 路径长度限制；不能通过缩短测试路径掩盖客户安装路径风险。上线前须核对客户安装根路径及最深目标路径。测试设备/客户设备升级均应安排无活跃高成本任务的窗口，升级后核对当前 Release、健康、画布、素材与更新作业；进入 `RECOVERY_REQUIRED` 时禁止重复点击，先导出诊断并人工核验。

本页是交付边界与可重复验收入口，不代替 GitHub Release 页面上的准确目标提交、三资产 SHA-256 与发布状态。候选未发布前不得称客户可升级。
