# v2026.10.2 修复版发行记录

记录日期：2026-10-14。负责人已批准在 #123、#157、#158 独立审查合并后，构建同源发行包，完成正式 10.1 → 新版的数据保留与必要失败恢复验证，再发布到更新中心。该批准不包含客户设备或生产升级。

本记录随发行源码保存；准确 commit/tree、Release ID、资产与最终验证结果以同次构建记录、GitHub Release 和 [CURRENT](../CURRENT_PROJECT_STATUS.md) 为准。写入 VERSION 不等于已发布，正式 10.1 的 refs/资产不覆盖。

## 用户可见变化

- ComfyUI 的文件名前缀恢复为普通文本参数，旧错误配置直接兼容。设置页、普通画布和智能画布共用输入映射，真正缺图时指出缺少的输入；配置读取期间避免双击重复提交，级联失败不继续消费旧结果。操作仍是选择工作流、连接素材、运行、接收输出。
- 长期接入的 Zhenzhen 图像模型按内置能力构造请求并限制不支持的画幅/分辨率；普通用户在生成节点管理个人显示模型列表。临时模板仅用于尚未内置的新模型，不作为日常使用步骤。
- 管理后台使用可操作的页面确认处理账户创建、停用/恢复及软删除；管理员与超级管理员权限继续由服务端限制，普通管理员不能创建同级或更高权限账户。
- 普通异步图像任务保留已受理供应商 ID。中断后可从原画布手动查询原任务，成功图片归档到本地；查询或下载失败保留未知状态，允许再次查询，不自动重新付费生成。批次与旧错误部分缓存也经过归档检查。
- 明确网络断线、未知响应和 5xx 后的付费提交止损，修正 Responses background/SSE 的重复 POST 路径；明确 4xx 拒绝后的协议协商保持兼容。
- 保留当前 Windows 固定入口和按需更新。启动当前版本不要求更新；管理员在更新中心单独确认。已合并的安装、缓存清理、保留数据卸载/重装、目标执行器与连续升级能力按其来源和实际验收范围交付，失败保留必要恢复及停服离线维护路径。

## 发行与兼容契约

构建使用干净 Git 提交、既有固定 Python Runtime、同源 EXE 和 Setup；Manifest、inventory、升级路由和维护资产绑定同次来源。数据库采用已知 v2 同 Schema 契约，本版不实施新业务 Schema 迁移。仅声明实测的准确 10.1 来源路由，其他历史来源不猜测兼容性。

发布前验证使用开发机合成安装副本、合成账号/画布/素材：正式 10.1 包正常启动和登录，认证更新执行，目标健康与业务数据保留；另一独立 10.1 副本验证目标启动失败后恢复原版本及业务。准确结果在发行资产验证记录留存，不将单元测试、受控协议或静默操作替代 GUI/客户验证。

## 保留的限制

真实付费供应商/GPU、自定义 ComfyUI 节点、PS 企业登录与 Chrome 扩展宿主、完整 GUI/历史版本矩阵、未知未来 Schema、全部在线多跳续接和客户生产设备仍按各实施记录的边界解释。普通异步图像续查不是完整任务中心、Provider Attempt/费用账本、视频或所有专属协议恢复；Responses 后台 ID 的长期恢复尚未覆盖。

EXE/Setup 的签名状态以构建记录为准；未签名资产不要求关闭 Windows 安全保护。当前仍是单台 Windows 主机部署，Linux/云和 500+/200+ 容量是长期约束，不在本版宣称已支持或已验证。
